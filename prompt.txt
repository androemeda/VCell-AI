## WHAT WE ARE BUILDING

### Goals
1. User-controlled model switching — user can choose between "openai" and "local" model in the chat UI
2. Automatic silent fallback — when a user's OpenAI budget is exhausted, requests are rerouted to the local LLM with no error shown to the user
3. Per-user budget management — org admins set individual token/spend limits per user from LiteLLM's built-in dashboard
4. Persistent tracking — usage and budgets survive container restarts, stored in Supabase

### Tool: LiteLLM Proxy
- Runs as a new Docker container in docker-compose.yml
- FastAPI calls it at http://litellm:4000 (internal Docker network, never exposed raw to the internet)
- Exposes an OpenAI-compatible API — minimal changes to existing FastAPI LLM call code
- Connects to Supabase directly for persistent budget/spend storage
- Has a built-in admin dashboard at /ui (to be proxied behind auth in production)
- Langfuse integration: LiteLLM proxy can send traces to Langfuse via litellm_config.yaml — use this instead of the current per-client langfuse.openai wrapper

### LiteLLM model names to use
- "openai-model" → OpenAI GPT-4o (or whatever model the org uses)
- "local-model" → self-hosted Ollama/vLLM on a separate GPU server

### User identity mapping
- LiteLLM user_id = Auth0 sub (e.g. "auth0|abc123")
- Each user gets one LiteLLM virtual key, stored in Supabase users table as litellm_virtual_key column
- Virtual keys are permanent (no expiry) unless manually revoked
- On first login, FastAPI provisions the user in LiteLLM and stores the key in Supabase
- On every LLM request, FastAPI fetches the virtual key from Supabase and passes it as the Authorization header to LiteLLM

### Budget and fallback behaviour
- Budgets are set in USD (e.g. $10.00) per user, per period (e.g. "30d")
- When budget is exhausted, LiteLLM silently falls back to local-model
- Fallback is configured in litellm_config.yaml — no code needed in FastAPI for this
- The frontend should display a subtle indicator when the local model is being used (check "model" field in response)
